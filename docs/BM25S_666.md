# BM25S: recuperación léxica sintética dentro del producto

El incremento añade `bm25s / retrieval.check` al mismo Engine, worker, CLI/MCP,
flujo con dependencias y SQLite. El estado calculado alcanza **Lote A 1/164 ·
Lote B 0/163**, 283 adaptadores, 56 piezas de construcción y 327 pendientes.
Las 39 incorporaciones anteriores quedan fuera del nuevo conteo. No hay
servicios certificados en producción: `live_verified=0`.

## Operación delimitada

La entrada exige `dataset: demo`: entre uno y ocho documentos de uno a dieciséis
identificadores enteros entre 0 y 7, una consulta de uno a ocho identificadores
entre 0 y 15, y `k` entre uno y el número de documentos. Los identificadores
8–15 permiten comprobar consultas sin coincidencias. Se rechazan texto libre,
rutas, URLs, modelos, selección de backend y campos adicionales.

Los tokens se construyen internamente. El BM25 original usa la variante Lucene,
`k1=1.5`, `b=0.75`, precisión float64 y los backends NumPy originales. Ejecuta
`index`, `get_scores` y `retrieve`. Una referencia escalar independiente
comprueba todas las puntuaciones y el top-k, incluidos empates, repeticiones y
términos desconocidos. El resultado conserva únicamente recuentos y metadatos
de alcance; no salen documentos, tokens, posiciones ni puntuaciones crudas.
No demuestra relevancia semántica ni resultados comerciales.

atestación independiente ni prueba de reproducción binaria. El aislamiento de
dependencias presupone un administrador y un entorno de ejecución confiables.

## Aceptación observada

Después de la interrupción del entorno se preservaron los cambios, se incorporó
el checkpoint remoto `f282cef` y se construyeron perfiles limpios de BM25S,
NumPy y txtai. Se ejecutaron seis casos: términos repetidos, empates, consulta
desconocida, multiplicidad, límites máximos y un único documento.

El flujo conjunto entrega `analysis-retrieval.result.matching_documents` a
txtai y comprueba que su agregado coincide. También verifica cero clientes
pagados, ausencia de texto interno en SQLite, rechazo de módulos o dependencias
inyectados, MCP, CLI y replay después de reiniciar Engine sin volver a ejecutar
el SDK. Pasan **926 pruebas unitarias y de contrato**.

- Contrato: `sources/contracts-bm25s666.json`.
- Aceptación local: `evidence/accepted/bm25s666-joint-local-20261115.json`.
- Recibo local: `evidence/accepted/bm25s666-build-local-20261115.json`.

La aceptación local declara `os_network_isolated=false`; no se atribuye una
garantía que no se observó. El job `bm25s666` de runtime reconstruye los perfiles
y exige aislamiento de red del sistema operativo para su aceptación. Los tres
workflows del commit vigente deben observarse por separado. Ningún caso demo,
replay o prueba HTTP sintética cuenta como producción.

El perfil se selecciona mediante `VERDUGO_BM25S666_PYTHON`, únicamente desde la
configuración del operador. La operación permanece deshabilitada por defecto,
con revisión de runtime y licencia exigidas. No descarga pesos, invoca LLM,
publica contenido, manda mensajes ni autoriza acciones externas.
