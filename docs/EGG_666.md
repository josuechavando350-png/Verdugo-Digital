# Egg: congruencia sintética finita

`egg / congruence.check` integra el código original de
[`egraphs-good/egg@73975c9819efb4af2f3c6c1b44fa53f8c5742574`](https://github.com/egraphs-good/egg/tree/73975c9819efb4af2f3c6c1b44fa53f8c5742574)
en el mismo Engine, CLI/MCP, workflow e inventario de Verdugo Digital.
Está deshabilitado por defecto y requiere revisión local del operador.

## Contrato y límites

La entrada contiene `dataset=demo`, entre uno y dieciséis nodos sintéticos y
hasta dieciséis igualdades entre índices. Cada nodo tiene un operador entero
entre 0 y 7 y hasta dos hijos anteriores. No se aceptan texto de programas,
reescrituras, comandos, rutas, modelos, credenciales ni URLs. La igualdad de
los operadores sintéticos no expresa una afirmación sobre el mundo real.

El driver fijo usa `SymbolLang::new`, `EGraph::add`, `union`, `rebuild`, `find`
y `number_of_classes` originales. La matriz de equivalencia se compara en
memoria con una partición finita independiente; también se comprueba el número
de clases. No se presupone inyectividad ni conmutatividad. Solo salen recuentos
de nodos, clases, pares equivalentes, igualdades suministradas y comprobaciones.
No se retorna ni conserva el grafo ni su matriz.

Los planes SQLite de Egg y BM25S proyectan sus entradas a recuentos y una
huella SHA256. La huella de idempotencia de Engine sigue vinculada a toda la
entrada y a la configuración; cambiar el contenido conservando los recuentos
no permite reutilizar la clave. El worker recibe los datos completos únicamente
en memoria. Esto no convierte las demás operaciones históricas del producto
en un almacén sin datos personales: su revisión de privacidad es independiente.

## Fuente y licencias

`sources/contracts-egg666.json` contiene los 40 blobs de Egg y los 14 de
`symbol_table` en su revisión Git exacta
`a716c39a4aa4757c910c93fc10c5c7fa8f467133`, con SHA Git y SHA256. Conserva el
hash del archivo fuente, los tres archivos del driver, el lock de Cargo,
el grafo resuelto de 24 paquetes y las licencias originales seleccionadas.

Se usa `default-features=false`, opción ofrecida por el manifiesto original;
no se modifica Egg ni se eliminan dependencias obligatorias. Los 21 paquetes
de crates.io se fijan por checksum y se comprueban antes de ejecutar scripts
de compilación o macros. Se selecciona MIT cuando el original permite
`MIT OR Apache-2.0`; `foldhash` usa Zlib y `unicode-ident` exige además
Unicode-3.0. Ambas adiciones fueron autorizadas por Josue. Las licencias se
leyeron en el commit original y coinciden con los bytes de cada paquete.

Las identidades transferidas se conservan: `servo/rust-smallvec` pasó a
`smallvec/smallvec`; `mvdnes/spin-rs` pasó a `zesterer/spin-rs`, cuyo repositorio
archivado señala su origen actual en Codeberg. Los dos commits seleccionados
de Spin se comprobaron allí; no se sustituyeron por una versión de GitHub.

La revisión cubre esas fuentes y dependencias del perfil delimitado. No
certifica todas las funciones opcionales, el compilador, la biblioteca estándar
de Rust, las bibliotecas del sistema ni la distribución completa del producto.
`distribution_license_closure_verified=false` permanece visible.

## Instalación y aceptación explícitas

En Linux con Python 3.12 y Rust 1.100.0 preparados por el operador:

```bash
python tests_runtime/install_egg666.py --prefix /tmp/verdugo-egg666
python tests_runtime/install_content666.py
VERDUGO_EGG666_ROOT=/tmp/verdugo-egg666 \
VERDUGO_CONTENT666_PYTHON=/tmp/verdugo-content666/bin/python \
python tests_runtime/accept_egg666.py --out /tmp/egg666-evidence.json
```

El instalador exige un directorio nuevo, verifica fuentes/licencias antes de
compilar, usa el lock sin red durante el build y comprueba las dependencias ELF.
Guarda el binario, los avisos y un recibo con sus hashes. El runtime rechaza
binarios/recibos modificados, rutas inseguras y permisos de escritura ajenos.
El recibo depende de la confianza en el administrador y no es una atestación
independiente ni una demostración de compilación binaria reproducible.

Pasaron siete casos por Engine, 200 comparaciones deterministas independientes,
seis entradas rechazadas por el propio ejecutable y alteraciones de binario y
recibo. El flujo Egg → txtai concilia el recuento de clases por CLI/MCP, comprueba
SQLite, cero llamadas externas, cero clientes pagados y replay después de
reiniciar Engine sin ejecutar otra vez las bibliotecas.

La evidencia local está en `evidence/accepted/egg666-*-local-20261115.json`.
No afirma aislamiento de red del sistema operativo. El job `egg666` repite
la aceptación bajo `unshare --net` y conserva sus artefactos por commit.
El estado exacto de los tres workflows está en PR #25. Ningún resultado eleva
`live_verified`, autoriza campañas ni certifica producción.
